The hand-kept file: what each side reads

One file, four lists and the fög edition (US-23). Every fact carries its source URL and checked_on. The site reads names, kinds, shares and sources; the check reads everything; the maintainer-only notes are removed from the bundle as _readme is today. Database tab for the fields.

Decisions on this layer

Settled
  • No HTTP API and no fetch at run time: the media data is embedded at build time.PRD-0001 §6PRD-0001.US-12
  • One hand-kept file holds media, companies, holders and holdings; its schema lives in src/types.ts.PRD-0001.US-23
  • Medienmonitor is read by hand; no script scrapes it, and the file says so.PRD-0001.US-23Research-0003
  • The register is read by UID from Zefix linked data, without credentials, into a generated file; the command never edits the hand-kept file and a failed fetch writes nothing.PRD-0001.US-25
  • Staleness after 180 days warns, never fails.PRD-0001.US-23PRD-0001.US-18
  • No "Propriétaire" line without a source; disputed holdings show both holders.PRD-0001.US-20Research-0003, ruling 2
  • Errors and removals go to the owner's address by e-mail, not to a public issue.PRD-0001 §8
  • The page names Medienmonitor (Publicom for OFCOM), the register and the fög as its sources.PRD-0001.US-20PRD-0001 §6
Left to the implementation
  • The names of the file, the command and the second script: the sheet's are working names.
  • The SPARQL query itself and how many UIDs it asks for at once.
  • Whether the address of the media page keeps a territory segment.
  • Whether the check also reads the generated register file once it exists.
