No database: two new JSON files

As for the rest of the site, the "tables" are JSON files in data/, checked by npm run check and copied into the script at build time. The slice adds one file kept by hand and one generated by a command. Expected rows are those of the mockup's data, read on Medienmonitor on 2026-11-17; US-23 re-checks each line against Medienmonitor before the file is committed.

The mockup holds 85 links: 38 to a medium, which become the medium's publisher field, and 47 between holders and companies. Three of the 38 come from an association or foundation (Le Temps, Le Courrier, Canal 9); for Le Temps and Le Courrier the mockup writes the publisher as "à relever au registre du commerce", so those two publishers are to be sourced before the file passes the check. Reused unchanged: territories.json, whose region names the media's regions follow.

Settled by the owner (2026-11-18). A removal keeps a fingerprint of the name, not the name, so the public repository does not show it in data/media.json. Two limits stay: someone who already suspects a name can test it against the fingerprint, and the name remains in the git history of the versions before the removal.

Decisions on this layer

Settled
  • The media data lives in one hand-kept JSON file, not in code; adding or correcting an owner is data work only.PRD-0001.US-23PRD-0001 goal 5
  • A holding stores the share as published, or none; a "Propriétaire" line exists only when a source names a holder.PRD-0001.US-20Research-0003, ruling 2
  • The fög value is a sourced fact (value, edition, source, check date), updated when the fög publishes.PRD-0001.US-22
  • A person is stored with name and share only, with source and check date; after a removal, with a fingerprint of the name only.PRD-0001.US-24Research-0003, ruling 3
  • The register's answer lives in its own generated file, apart from the hand-kept data, and is never edited by hand.PRD-0001.US-25
  • The data is embedded at build time; nothing is fetched at run time.PRD-0001.US-12
