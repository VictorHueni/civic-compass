What each module gains

The slice follows the site's rules: TypeScript, English names, pure modules with no DOM and no data import for whatever computes what a page shows, so node --test and the check load them directly. New modules are marked "new"; the others gain what is listed.

Decisions on this layer

Settled
  • Réseau uses Cytoscape.js with the fcose layout, installed with npm and bundled at build time: the site's first runtime dependencies.PRD-0001 §6PRD-0001 §8
  • Soleil is drawn by the site's own SVG code, as the half-circles are; ECharts is not used.PRD-0001 §8
  • The graph code is a second script, loaded only when the media page opens, so the rest of the site keeps its weight.PRD-0001 §8PRD-0001.US-21
  • Everything works from dist/index.html with no network: both scripts are classic scripts, not ES modules.PRD-0001 §6PRD-0001 goal 4
  • The site and the check read the media data through the same pure module, so a rule holds in both.PRD-0001 §6
  • The 180-day staleness rule is the one shared by every hand-kept record.PRD-0001.US-23PRD-0001.US-18
  • No script reads Medienmonitor; the register is read by a maintainer command, never by the site.PRD-0001.US-23PRD-0001.US-25
Left to the implementation, answered by the build
  • How the second script receives the data and the callback (a global set by the first script, or the data embedded in both). Built: the second script registers window.civicMediaGraph; the data stays in the first and is handed over with each call and its callback.
  • How media.ts is split between lists, card and switch. Built: one module writes the page, the card, the switch and the loader; what it shows comes from media-model.ts.
  • Whether Soleil's SVG code lives in the second script or the first; the size budget of each script. Built: in the second, with Cytoscape; site.js 233 KB, media-graph.js 570 KB minified.
  • Whether the offline run becomes an automated test. Not yet: it is run by hand with Chromium (increments 14 and 15); automating it needs a browser in CI.
