The owner wants the site to show who sits where, for the Confederation and the six covered cantons (GE, VD, VS, NE, JU, FR). Today the site shows one such fact: National Council seats per national party, generated by `npm run seats` from the OFS 2023 results into `data/seats-national-council-2023.json` (national rows only, total 200 enforced by `npm run check`). The project rules apply to every new figure: no fact without a source and a date, voters see only verified data, a figure generated from an official source lives in its own generated file, the static site bundles its data at build time with no runtime fetch. This note asks, institution by institution, which source can supply that data and whether it can be generated by a command or must be kept by hand.

**How confidence is rated here.** The skill's rubric is written for regulatory topics; this note maps it as follows. ★★★★★: the body that holds the office or keeps the official record publishes the data, read directly by a script or in the raw page (Parliamentary Services, OFS, a canton's chancellery or parliament). ★★★★: the same kind of source read only through a summarising fetch, or an official source that itself says it is not kept current, or a party's own page about its own leadership (self-published, often undated). ★★★: an independent aggregator of official data (OpenParlData) describing itself. ★★: encyclopaedia, crowd-edited data (Wikidata) or a search-engine summary of a page that could not be opened. Figures counted by this research from raw data (rather than read in a source) are marked "computed here". All downloads were made on 2026-11-16 into a scratch folder outside the repository; nothing downloaded was executed.

## Q1: Which source gives the 7 Federal Council members with party and department, with a date, and can a script read it?

### Context

The Federal Council is the most visible institution and the smallest data set (7 people, one department each). Its party composition also answers the hidden fact `federal_council_seats` in `data/parties.json`, kept with a null source since 2026-11-16 (PRD-0001 §8). Changes are rare (an election in December, a resignation, a new department split), so the question is mostly which source to cite and whether one script can read it.

### Finding

**Names, party and canton of the 7 members can be read by a script** from the Parliament OData service, which lists them as `MemberCouncil` rows with `CouncilAbbreviation` "CF", updated the same day. **The department is not in OData**; it is on the admin.ch members page (which refuses `curl` with 403) and in the Federal Chancellery's annual brochure "La Confédération en bref 2026" (which `curl` can download, but as a designed PDF, not data). The brochure also gives the year each member joined, which OData's `DateJoining` does not (it shows 2026-01-01 for members in office since 2016 to 2019).

The legacy OData endpoint is scheduled to be switched off "d'ici fin 2028"; its successor `ws.parl.ch` needs an API key obtained by registration. The terms require the attribution «Services du Parlement de l'Assemblée fédérale, Berne», the download date shown clearly, unchanged content, and no presentation as an official publication.

Interpretation, flagged as such: with 7 rows that change about once a year, a hand-kept file (names, party, department, `since`) citing admin.ch and the brochure is the least work; OData is better used to check that file than to replace it.

### Implication for ADRs

- **Future ADR "Sources of institutional composition data":** Federal Council members hand-maintained, source admin.ch page plus "La Confédération en bref" for the year of entry; the generated OData file (Q2) cross-checks names and parties in `npm run check`. Rules out OData alone (no department).
- **PRD-0001 US-06:** `federal_council_seats` per party can then be computed from the hand file and shown with the admin.ch source, unhiding a fact the PRD hides today.

### Finding

**Yes, the OFS file already used has per-canton rows** (`ebene_resultat` = "Kanton", 219 rows, 200 seats in total), so the existing `npm run seats` command can produce National Council seats per canton for the six cantons by reading one more level of the same file. **No, it does not reflect changes since the election**: it is the election result of 22 October 2023, last modified on 24 May 2024.

**The current composition comes from the Parliament OData service**, updated daily (latest `Modified` 2026-11-16), with names, canton, party and parliamentary group per member. On 2026-11-16 the national totals differ from the OFS result for two parties because one member moved from PLR to pvl on 2025-01-09, and because OData keeps two regional parties apart (PLD in Basel, Alternative-die Grünen in Zug) that the OFS counts under PLR and VERT-E-S. For the six covered cantons, the per-party counts are the same in both sources today (computed here).

Members' names are available from OData (current) or from the OFS candidates file (elected on election day).

### Implication for ADRs

- **Future ADR "Sources of institutional composition data":** extend `npm run seats` to write the per-canton rows (no new source, same OFS terms). Add one command that reads OData into its own generated file for the current composition, with the attribution and download date that the terms require.
- **Owner decision (see Recommendation):** show the election result (OFS), the current composition (OData), or both, and how to map OData's PLD and Al to the site's national parties.

### Finding

**The OFS table je-f-17.02.05.01.03 covers all six parliaments in one file**, with the year of the last election (GE 2023, VD 2022, VS 2025, NE 2025, JU 2025, FR 2026), seats by party family, footnotes naming the canton-only parties counted under "Autres" (LJS in GE, the VD and FR local lists), and a current version published on 2026-11-11 that already includes the Fribourg election of November 2026. **Current compositions differ from election day where members change group.** Geneva's own page shows LJS at 7 seats and 3 independents on 2026-11-16, where the OFS table has LJS 10 for the 2023 election. Vaud's page counts parliamentary groups (PS 31, Ensemble à Gauche et POP 7), not lists. The official cantonal pages are HTML only: GE and VD list members by group with counts, JU publishes a seat table, NE has a filterable member list without counts, FR sends to Parlinfo, and the VS parliament site is a JavaScript application whose composition could not be read. None offers a documented download of the composition, except VD's PDF and e-mail Excel.

**OpenParlData covers the six parliaments under CC BY 4.0 and is refreshed daily, but is not usable for seat counts today**: its "active" persons mix deputies, substitutes and executives, the Fribourg list holds about 30 deputies for 110 seats, Vaud 168 for 150, party labels are raw and the harmonised party is missing for most Valais deputies (computed here). Exact election dates read on official pages: VS 2 March 2025 (vs.ch), VD legislature from 1 July 2022 (vd.ch). Not read on an official page: GE (2023), NE (2025), JU (2025, legislature 2026-2030 per jura.ch), FR (8 November 2026 per a search summary of a PDF that returned 404).

### Data shape (sketch only, for `src/types.ts`)

```ts
/** Attribution block shared by generated files (the OData terms require the download date). */
interface DataSource {
  url: string;
  dataset_page: string;
  attribution: string;      // e.g. "Source : Services du Parlement de l'Assemblée fédérale, Berne"
  license: string;
  retrieved_on: string;     // AAAA-MM-JJ
}

/** Seats of one party in one body; party_id null when the source's party has no entry in parties.json. */
interface PartySeats {
  party_id: string | null;
  source_label: string;     // label as written by the source, e.g. "Autres (LJS)", "M-E"
  seats: number;
}

/** One body (a chamber, a cantonal parliament or government) at one point in time. */
interface BodySeats {
  territory: string;        // "CH" or canton code
  body: "national_council" | "council_of_states" | "federal_council" | "cantonal_parliament" | "cantonal_government";
  basis: "election_day" | "current";
  election_year: number | null;
  as_of: string;            // date of the election or of retrieval, per basis
  total: number;            // npm run check: sum of seats === total
  parties: PartySeats[];
}

/** A person holding an office, from a generated file or a hand file. */
interface Officeholder {
  name: string;
  territory: string;
  body: BodySeats["body"];
  party_id: string | null;
  party_label: string;      // as in the source, e.g. "sans parti"
  role?: string;            // "présidente", "vice-président"
  department?: string;
  since?: string;           // year or date
  source: string;           // URL
  checked_on: string;
  evidence?: string;        // hand files only: short quote from the source page
}

/** Added to Party: zero, one or several (co-)presidents. */
interface PartyPresident {
  name: string;
  role: string;             // "Président", "Co-présidente"
  source: string;
  checked_on: string;
  evidence: string;
}
```

Generated files wrap `BodySeats[]` and, for OData, `Officeholder[]` next to one `DataSource`; hand files hold `Officeholder[]` with per-row `source`, `checked_on` and `evidence`, like the existing link entries. The existing `Seats` type can stay as is for slice 1 (adding `by_canton: Record<string, Record<string, number>>`) and migrate to `BodySeats` later.

### Delivery order (one critical path)

1. **National Council per canton.** Extend `npm run seats` to the "Kanton" rows of the file already used; show the canton's National Council seats on the canton's party cards. Same source, same terms, smallest change.
2. **Federal parliament, current.** `npm run parliament` from OData: current National Council and Council of States by canton and party, with the terms' attribution and download date on the page. Includes the 7 "CF" rows used by slice 3.
3. **Federal Council.** Hand file with departments and years of entry, cross-checked with slice 2; unhides `federal_council_seats`.
4. **Cantonal parliaments.** `npm run cantonal-seats` from OFS je-f-17.02.05.01.03, with the per-canton party mapping; labels "au jour de l'élection".
5. **Cantonal governments.** Generated OFS counts (same command) plus the hand file of members, checked against the counts; Fribourg after the 29 November 2026 second round and the OFS update.
6. **Party presidents.** Hand entries in `parties.json`, 9 national first, then the 42 sections canton by canton.

Slices 1 and 2 are independent of each other and of slice 4; the order above is a recommendation, not a dependency.

### Owner decisions needed

1. **Election result or current composition.** For the National Council, show the OFS 2023 result, the OData current composition, or both (they differ nationally, not in the six cantons today). For cantonal parliaments only the election-day figure is generated; showing current group sizes (GE: LJS 7 and 3 independents) would mean hand-kept counts.
2. **Parliament API generation.** Use the legacy `ws.parlament.ch` (switched off by end 2028 at the latest) or register now for an API key to the new `ws.parl.ch` (the key must stay out of the repository, so the command would run on the maintainer's machine or with a CI secret).
3. **OData terms.** The terms say "Le contenu des données doit rester inchangé" and require the download date to be shown. Counting members per party and mapping labels such as "M-E" or "PSS" to the site's parties is an interpretation of "unchanged"; the owner decides whether that is acceptable or asks the Parliamentary Services.
4. **Regional parties in national totals.** Whether OData's PLD (Basel) and Al (Zug) are counted under PLR and VERT-E-S, as the OFS does, or shown apart.
5. **Reading xlsx.** The OFS cantonal tables exist only as xlsx: write a small reader in the tool (Node can inflate the zip; the XML is simple) or add a pinned development dependency, against the current rule of three development dependencies.
6. **Fribourg in transition.** Show the Grand Conseil elected on 8 November 2026 (already in the OFS table) from now, or the sitting one until the new legislature starts; record the new Conseil d'État only after the second round.
7. **Members' names.** Whether the site lists people (federal chambers, cantonal governments, party presidents) or only seat counts; names add review work and, for parties without a named president (PST-POP, solidaritéS on the pages read), an explicit "non indiqué".
8. **Staleness rule.** Whether `npm run check` warns or fails when a hand-kept person record has not been checked for 180 days.

None of these changes is implemented by this note.

### Owner rulings (2026-11-16)

1. **Election result or current composition:** cantonal parliaments show the latest election result with its date (OFS, generated); the federal chambers show the current composition (Parliament API, generated).
2. **Parliament API:** the new `ws.parl.ch`. The owner registered; the key lives outside the repository in `~/.config/civic-compass/env` (`PARL_API_KEY`, mode 600) and is read by the generating command only. Checked with the key on 2026-11-16: the OpenAPI document is public at `https://ws.parl.ch/doc/v3/api-docs` (title "Swiss Parliament Open Data Webservice (OWS)", version 1.0.0); the key goes in the `X-API-KEY` header; filters use the `q` parameter (`eq(active,true)`, strings in double quotes); `/api/v1/persons?q=eq(active,true)` returned 255 active persons with council, party and canton; the schema `FederalCouncilMandateV1` carries `department`.
3. **Terms of use:** counting members per party and mapping labels to the site's parties is accepted, with three safeguards: the generated file keeps the Parliament's data unchanged (raw), the mapping is stored apart; every figure shown carries "Source : Services du Parlement de l'Assemblée fédérale, Berne" and the download date; the site keeps stating that it is independent and not official.
4. **Regional parties:** PLD (Basel-Stadt) is counted under PLR and Al (Zug) under the Greens, as the OFS does; the original label stays in the raw data and may be named on the card ("dont 1 PLD Bâle-Ville").
5. **Reading xlsx:** a small reader written in the tool (zip and XML with Node's built-ins), no new dependency; a library only if the reader meets a case it cannot handle.
6. **Fribourg:** the Grand Conseil elected in November 2026 is shown now, labelled with its election date; the new Conseil d'État after the second round of 29 November 2026, once published by the OFS and checked.
7. **Names:** names, party, canton and function only (no photo, address or date of birth) for the Federal Council (with department), the Council of States and National Council members of the chosen canton, the cantonal governments (with department) and party presidents; cantonal parliaments show seats per party only.
8. **Staleness:** `npm run check` warns, never fails, when a hand-kept person record (cantonal government, party presidency) was checked more than 180 days ago. Party presidencies are shown only when sourced, never as "unknown", as `presidency {names, source, checked_on}`.
